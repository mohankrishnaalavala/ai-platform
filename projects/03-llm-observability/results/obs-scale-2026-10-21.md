**Scale from zero: failed (04:03:29Z to 04:12:25Z), no probes.**
- vLLM scaled to 0 on its own (`04:10:42Z no vLLM pod`), then the GPU node went (`04:12:25Z no GPU node`).
- The script then reopened the gateway port-forward. In the same second, the probe's first request was refused: `ConnectionRefusedError: [Errno 111] Connection refused`, in `new_key`.
- **Cause, reproduced locally:** `stop_port_forwards` (`tests/lib.sh`) signalled the old `kubectl` but didn't wait for it to exit.
  - The new port-forward couldn't bind the port while the old one still held it, so it quit.
  - The readiness check got its answer from the old one before that one went. Then nothing was listening.
  - A stand-in `kubectl` that keeps the port for 1.5 s after the signal showed the same failure ("Address already in use", then nothing on the port).
- So vLLM scaling from 0 to 1 on gateway traffic is still unmeasured.
